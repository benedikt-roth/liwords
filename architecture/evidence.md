## Method and source hierarchy

Reviewed 2026-11-13 at `739d748c26e82067424f2ea5c5c7958bcd197485`. Source links are relative to this checkout; the revision identifies the baseline. The analysis prioritizes executable wiring and handlers, then persistence/query definitions, relevant tests, and finally README/comments and public manuals. SQL migrations describe schema evolution; current queries and code establish which representations are actually used.

The E-identifiers are a compact cross-document source index. Each entry names the files and relevant symbols or behavior, so readers can verify claims without relying on unstable line numbers. DDD context boundaries, aggregate candidates and named business facts are inferred; they are not declarations that the code follows a formal DDD architecture.

## Secondary sources

Consulted on 2026-11-13:

- [Woogles guides](https://blog.woogles.io/guides/) and [game settings guide](https://blog.woogles.io/guides/2025-07-11-what-game-settings-should-i-use/): user-facing dictionary, challenge and timing vocabulary. Used only to corroborate language; handler validation determines supported settings.
- [IRL tournament guide](https://blog.woogles.io/guides/2025-07-11-using-woogles-for-irl-tournaments/): corroborates face-to-face result entry, scorecards, rounds and pairing concepts. It describes a user workflow rather than all current API permissions.
- [Public docs](https://woogles.io/docs): the web reader returned the JavaScript shell. The corresponding [local manual](../liwords-ui/src/docs/manuals/streaming.tsx) was inspected directly, including the distinction between event broadcast slots and personal stream slots.
- [Open protocols](https://github.com/woogles-io/open-protocols) and its [CGP specification](https://github.com/woogles-io/open-protocols/blob/main/cgp/README.md), blob `e3bb5a89232ffbcd8a6bfec588b227f609374ebd`: CGP describes a crossword position rather than its full history and supports UTF-8. This is a vocabulary/interchange reference, not a deployed service or proof that every protocol in that repository is implemented here. Local protobuf contracts remain the application API source of truth.

## Uncertainty and discrepancy register

| Item | Evidence / assessment | Consequence or follow-up |
| --- | --- | --- |
| Production topology | Compose is explicit; workflow builds images and uploads frontend assets, but full ingress, replicas, network boundaries, scheduler definitions and deployed flags are absent. | Confirm with operators before using this as a deployment/runbook diagram. |
| Domain boundaries | The proposed contexts share `entity`, protobufs, SQLC queries and database access; handlers cross them directly. | Validate language/ownership with maintainers. These are analytical boundaries, not completed modularization. |
| Gameplay migration | `pkg/omgwords/README.md` describes a future gameplay service; current wiring keeps it inside the API. `game.Cache` has a historical name; turn reconstruction is explicitly disabled in the served native load path. | Read implementation before relying on comments or package names. No claim of completed engine replacement. |
| Archive configuration | History upload is asynchronous and recoverable through a maintenance sweep; runtime behavior depends on bucket and flags. | Archive upload frequency and production coverage were not measured. |
| Completion consistency | `pkg/gameplay/end.go` publishes and updates several stores in sequence; some failures are logged rather than propagated. | Do not infer a distributed transaction, durable domain event log or exactly-once delivery. Repair/recalculation matters. |
| Analysis eligibility | Protocol retains `NOT_A_PLAYER`; `RequestAnalysis` explicitly permits any authenticated user to request a completed supported game. | Document observed handler behavior, not a restriction inferred from the enum. |
| Privacy semantics | Collection `public` affects listings; a direct read does not establish full private-resource access control. Annotation `private_broadcast`, tournament `private_analysis`, rack censorship and verification-image access serve different purposes. | Confirm intended product semantics before treating all “private” flags as equivalent authorization guarantees. |
| Event history vs event sourcing | Per-turn records and protobuf notifications exist, but authoritative state, fallback histories and projections coexist. | Avoid describing the entire platform as event sourced or assuming replay alone restores all side effects. |
| Annotation concurrency | Owner checks exist, but `GameDocumentStore.GetDocument` explicitly does not lock read/modify/write. | One owner is not equivalent to one concurrent client; simultaneous edits need separate consistency work. |
| External bot/worker | Bot wiring is present; external Macondo bot and volunteer-worker implementations were not audited. | Their internal scalability, failure behavior and exact deployment remain outside scope. |
| Currency of public guides | Guides and protocol reference evolve independently of this fork. | Use them for language and scenarios; prefer the reviewed source for current implementation. |
| Validation scope | Static code/schema/test review and documentation checks; no production inspection or live end-to-end run. | Runtime availability, throughput and operational correctness remain unverified. |
